# 金融科技项目立项与管理层汇报

## 目标

把项目事实表、供应商材料、变更卡和文档模板转化为可追溯的Word立项报告、管理层决策PPT、问题台账与核验记录。以证据约束数字和结论，不补造数据，不把供应商主张写成事实或保证。

## 适用边界

- 处理经授权或已脱敏的金融科技项目材料。
- 用于有事实表、外部供应商、管理层决策或金融风险披露要求的项目。
- 不用于没有事实表的纯文案创作、无外部供应商的普通内部项目，或与管理层决策和金融风险无关的通用材料。
- 不替代真实的授信、交易、投资、合规或风险处置决策。

## 开始前检查输入

确认并读取以下材料：

1. 项目事实表（XLSX）：业务数字、单位、来源、证据类型和事实表行号。
2. 供应商方案摘要。
3. 管理层变更卡（如有）。
4. Word模板和PPT模板。
5. 风险清单与口径说明（如有）。

事实表缺失时停止生成正式Word和PPT，输出缺失材料清单并请用户补充。其他材料缺失时说明影响，把相关内容标为“待确认”，不得自行填补。先检查文件是否可读、模板是否完整、项目名称和版本口径是否明确。

按文件类型调用相应的文档、演示文稿、电子表格和PDF能力。创建或修改DOCX、PPTX、XLSX后，执行对应的渲染或结构核验；如果环境缺少渲染组件，明确记录限制。

## 证据优先级

按以下顺序解决冲突：

1. 经确认的管理层变更卡覆盖被其明确调整的旧口径。
2. 项目事实表控制所有未被变更卡明确调整的数字和业务事实。
3. 供应商方案只能证明“供应商提出了该主张”，不能证明效果已经实现。
4. 模板只控制结构和版式，不控制业务事实。
5. 推算、假设和经验判断不得覆盖上述证据。

变更卡只改变明确列出的事项。预算或周期变化不会自动改变其他业务事实、供应商效果、收益情景或风险结论。

## 六步工作流

### 第一步：建立事实—主张对照表

完整读取所有输入，提取正文段落、表格、图表标签、指标卡、页脚和备注中的项目名称、数字、单位、时间、范围、效果与结论。

逐项和事实表比对，并标记：

- `事实`：有事实表行号或变更卡编号支持。
- `供应商主张，尚未验证`：来自供应商材料的效果、收益、性能或实施承诺。
- `假设`：为分析建立、但没有事实证据的条件；必须显示假设条件。
- `待确认`：材料缺失、来源不清或无法判定。
- `冲突`：数值、单位、范围、时间或措辞与高优先级证据不一致。

输出事实—主张对照表，至少包含：主题、当前内容、数值、单位、标签、来源文件、具体位置、事实表行号或变更编号、限制条件、处理结论。

### 第二步：诊断并生成问题台账

扫描所有材料，按以下顺序处理：

1. 金额、单位和数量级硬错误。
2. Word、PPT及参考材料之间的数字不一致。
3. 遗漏风险、成本排除项或决策边界。
4. 把供应商主张写成保证、事实或确定上限。
5. 信息层级、缺页、占位符和版式问题。

每个问题必须写清：

- 唯一编号与风险等级；
- 所在文件、页码/章节/表格/指标卡等具体位置；
- 当前内容；
- 正确依据及其具体位置；
- 问题类别；
- 可能影响的管理层判断；
- 建议修复方法；
- 状态与复测结果。

不得只写“数字不一致”或“表达不好”。使用 `references/quality-gates.md` 中的问题台账字段和分类。

用户要求“只诊断”时，到本步骤停止，不改Word或PPT。把台账另存为新版本。

### 第三步：设计Word和PPT结构

在制作文件前输出制作/修复计划、结构和证据映射。若用户要求先确认，必须等待确认后再制作；未要求确认时，也不得在尚未解决会改变结论的关键冲突时直接生成最终文件。

Word采用以下章节流：

1. 封面
2. 执行摘要
3. 项目背景
4. 建设目标
5. 试点范围
6. 实施计划
7. 投入与收益
8. 风险与治理
9. 结论
10. 附录

PPT采用以下页面流：

1. 封面
2. 问题与证据
3. 试点方案
4. 投入与预期
5. 评价框架
6. 风险与治理
7. 待决策
8. 附录｜证据边界

PPT服务管理层决策，不得简单复制Word。每页只承担一个决策任务，用结论式标题和可追溯的关键证据。

执行以下硬规则：

- 预算和周期分别占用独立、对等的指标卡。
- 所有供应商数字就近标注“供应商主张，尚未验证”。
- 保留供应商原始区间，不得只取最优端点。
- 风险页覆盖隐私、误报、漏报、解释性、模型漂移、审计、供应商依赖、客户争议八类风险。
- 每个审批事项均带预算、周期、范围、扩展条件或叫停条件等边界。

### 第四步：从模板生成Word和PPT

克隆用户提供的模板并另存新版本，不覆盖原文件。尽量保留模板的主题、母版、版式、字体、表格样式和页码体系。

只填入已建立证据标签的内容：

- 事实数字附事实表行号或来源标识。
- 供应商效果使用原始区间并标注“尚未验证”。
- 待确认项不得伪装成正文结论。
- 假设与测算情景不得写成已验证ROI。
- 预算边界披露银行内部人员、数据治理整改、长期运维、额外接口、退出迁移成本五项是否纳入；来源不明确时写“未明确纳入”。
- 明确模型提供辅助判断，不承担最终拦截责任。

在变更记录中写明修改项、旧值、新值、证据编号、受影响位置、核验状态。历史旧值只允许出现在明确标识为历史的变更记录中。

### 第五步：执行Word—PPT一致性核验

逐项比较：

- 项目名称；
- 预算与单位；
- 周期与阶段划分；
- 试点原则和门槛评审；
- 业务事实及事实表行号；
- 供应商效果数字、区间和“尚未验证”标注；
- 风险条目；
- 成本排除项；
- 结论与决策措辞；
- 数据来源和证据边界。

发现不一致时回到第四步修复并重新核验。

根据变更卡生成“被替代口径词条表”，扫描正文、表格、图表、指标卡、备注和页脚。诸如“800万”“12个月”“全面上线”“取消人工”“保证实现”等词，仅在确已被当前证据替代时才视为旧口径；不得机械删除仍然有效的事实。旧口径只能保留在变更记录的历史值栏。

### 第六步：执行金融披露核验

确认：

- 预算是否说明五项成本排除边界；
- 供应商数字是否保留原始区间；
- 是否声明供应商效果“尚未验证”；
- 是否声明模型不承担最终拦截责任；
- 风险页是否覆盖八类风险；
- 结论是否区分“本次批准事项”和“试点完成后再决策事项”；
- 决策建议是否说清批准预算、周期、首阶段工作、扩展条件和叫停条件；
- 附录是否列明事实表、供应商材料、变更卡及待确认项。

未披露项写入问题台账，类别标为“治理”，修复后给出具体复测证据。

## 变更处理

收到新变更卡时，先保存当前版本，再输出“变更影响清单”。列出受影响的Word章节、PPT页、图表、指标卡、执行摘要、决策建议和核验规则。未经用户确认，不批量替换。

执行变更时：

1. 仅修改变更卡明确覆盖的事项。
2. 另存新版本。
3. 更新变更记录。
4. 重新执行第五、六步。
5. 保存变更影响清单和核验记录。

## 输出与版本管理

根据任务范围交付：

- 事实—主张对照表（XLSX）；
- 问题台账（XLSX）；
- 制作或修复计划；
- 立项分析报告（DOCX）；
- 管理层决策汇报（PPTX）；
- 一致性与披露核验记录。

所有文件使用清晰版本号，如V1、V2。保留原文件和上一个版本，不直接覆盖。最终回复列出交付文件、关键核验结论、仍待确认事项和任何技术核验限制。

## 完成标准

只有同时满足以下条件才算完成：

- 模板中无残留占位符。
- 所有业务数字可追溯到事实表行号或变更编号。
- 供应商效果均标注“尚未验证”，并保留原始区间。
- Word—PPT一致性清单全部通过。
- 已被替代的旧口径不出现在当前正文。
- 问题台账记录全部发现及修复复测证据。
- 风险页覆盖八类风险。
- 五项成本排除边界已在正文或决策页披露。
- 决策建议明确预算、周期、首阶段工作、扩展条件和叫停条件。
- 附录列出数据来源和证据边界。

任何一项未通过时，不宣称文件已完全核验；记录缺口、影响和下一步。

## 详细规范

需要建立台账字段、判断风险等级、执行旧口径扫描或记录核验结果时，读取 [references/quality-gates.md](references/quality-gates.md)。
